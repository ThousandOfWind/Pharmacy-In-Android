# 药箱备份与恢复

入口：**首页 → 更多 → 备份与恢复**。使用 Android 系统文件选择器，无额外存储权限，不访问账号或应用更新凭据。

## 使用

1. 「保存完整备份」：选择保存位置，生成一个 `pharmacy-backup-日期时间.zip` 文件，包含已保存的全部药品资料及照片。建议保留多个日期的备份，不覆盖唯一备份。
2. 「选择备份文件恢复」：读取并完整校验备份，展示备份时间、药品/照片数、预计新增和重复数。
3. 「确认合并恢复」：重新核对现有记录，仅添加缺少的库存；不更新、覆盖或删除现有药品。取消或校验失败不改药箱。
4. 相同记录再次恢复会跳过。相同药名但资料、余量、日期、时间或照片不同的记录作为独立库存保留；不会靠药名去覆盖。恢复后可自行核对是否需要移除旧记录。

备份涵盖：名称、有效期原文、功效、备注、余量/单位、OCR 原文、创建/更新时间、标签、15 项药品/说明书字段，以及有序照片。未知余量与 0 分开；旧单位、未知日期及文字内部换行保留。**未保存草稿、撤销历史、相机临时文件、安装包和登录凭据不在备份中。**

## 隐私与保管

- 备份**未加密**，包含个人健康信息、药品、位置与备注。不要公开上传或发送给不可信的人。
- 保存到系统文件选择器中的云盘时，文件会由该云盘服务处理；本应用没有自行后台上传，但不保证云盘离线或私密。
- 应用不记录备份内容到日志、不嵌入账号/令牌。只向用户选择的文件 URI 写入，原药箱保留。
- 写入空间不足或文件服务断开时可能留下不完整的目标文件；应用提示备份未完成，用户应删除该文件，不能把它当成成功备份。App 无权承诺任意文件提供方的原子写入。
- 清缓存不会删除用户选定目录里的完整备份；卸载/清数据会删除本机药箱，所以必须先确保备份已成功。新旧安装签名不一致时，在旧版本导出后再规划迁移，不直接卸载。

## 格式与校验

备份 v1 为 ZIP：

- `cabinet.bin`：UTF-8 长度前缀的有版本清单，使用固定 v1 字段顺序，不依赖数据库文件或本机路径；拒绝未知版本、截断、非法长度、非法余量及未支持尾部数据。
- `photos/<sha256>.bin`：原始照片字节，SHA-256 命名；同一照片可在多个库存中复用，导出只保存一份。图片显示依赖原始文件内容，不依赖扩展名。
- 导入只允许上述精确命名，拒绝重复项、目录、任意路径、缺图、额外图片、CRC/哈希错误；使用私有随机暂存目录，不按 ZIP 文件路径解压。
- 上限：2000 条记录、每条 12 张照片、单张照片 20 MiB、清单 16 MiB、单项文字 1 MiB、压缩文件及总解压内容 512 MiB。不是任意规模数据库的备份工具。为保留旧记录，导入不要求旧日期/单位满足现行录入格式。
- 照片无法读取时**整个导出失败**，不偷偷生成缺图备份；不自动删除缺失的照片链接。
- 导出先制作完整本地快照，再写系统选定位置。恢复先校验，确认后在 Room 事务中插入；不更新现有行。恢复失败回滚插入并删除本次创建的照片，不触碰旧照片。
- 文件与数据库不是跨资源原子事务：若设备在复制图片与提交数据库之间突然断电，可能留下未引用的新照片，但不会清空已有药箱。后续单独清理不在本次范围。
- 重复判断按完整记录值与有序照片内容哈希，忽略本机 ID、URI。备份不是同步/版本回退工具；测试版改了数据再恢复旧备份不会自动撤销该改动。

## 验证与边界

新增 4 个必要 JVM UT：完整字段/旧值往返，照片归档往返与重复身份，恶意路径/缺图/损坏照片拒绝，数量/大小边界。保留其他核心规则测试，不新增 UI/仪器框架或第三方归档库。

构建与 Lint 只能验证编译/静态问题，UT 不代表 Android 文件提供方、实际数据库事务及进程/设备中断已实测。专用模拟器的实际导出、清除测试记录后恢复、照片查看和重复恢复需在本次清空测试数据获明确授权后验收；未获授权不自行运行或声明通过。
