# 药箱交互重构

当前手绘版的首页信息取舍、详情分组与渐进录入见 [paper-design.md](paper-design.md)。以下数据、OCR 和持久化规则不变。

## 目标与边界

首页服务于查看和寻找库存，不常驻录入表单。OCR 是输入助手，而不是药品数据库或用药决策工具。不推测药品名称、到期日期或疗效，不自动合并同名记录。

## 信息流

```text
我的药箱
  ├─ 搜索 / 筛选 → 药品卡片 → 详情
  │                            ├─ 更新余量 → 详情
  │                            ├─ 编辑 / 补拍 → 核对页 → 保存 → 药箱定位
  │                            └─ 移出药箱 → 药箱提示撤销
  ├─ 批量管理 → 逐条勾选 / 全选当前结果 → 确认移出 → 药箱提示整批撤销
  └─ 添加 → 拍照 / 相册 / 手动
              → 核对页 → 保存成功 → 药箱定位
```

- 空状态提供添加入口及次要的「从旧手机导入药箱」入口；有数据时列表是主角。
- 首页「更多 → 备份与换机」提供旧手机完整导出、新手机校验/预览/合并导入及完成核对；文件传递交给系统工具，系统备份配置不变，无自建服务器。导入不覆盖现有记录，查看药箱会清除搜索与筛选。步骤与隐私边界见 [backup-restore.md](backup-restore.md)。
- 首页保留照片/通用药盒线稿、名称、品牌/规格与标签摘要（前 3 个，多出的显示“＋N”）；异常有效期状态及已用完可见。完整有效期、带单位余量和全部标签在详情，标签直接展示而非折叠。首页不展示长功效、备注和 OCR 原文。
- 筛选“临期”是到期日在今天至未来 90 天之间，含边界；已过期是到期日早于今天。
- 日期未知单独呈现，绝不等同已过期或有效。
- 每条记录表示一份库存。同名但不同厂家、规格、批号或有效期应分别保存。
- 卡片可以显示品牌/规格摘要；详情中的说明书文字不截断，编辑入口在长说明书之前。

## 多标签整理与查找

- 标签可多选，非互斥分类；每条最多 8 个，每个最多 12 个字符，不允许换行或控制字符。首尾空白去除，空标签忽略，忽略大小写去重并保留首次写法。
- 常用标签分为用途整理、使用方式、备用场景和保存提示，具体词表见 README。仅由用户选择，不基于 OCR、药名或功效自动赋值，不构成用药建议；用途、方式及保存条件应核对包装。
- 添加与编辑页可点击常用词、复用当前库存已有的自定义标签，也可输入新标签。已选标签点击移除。自定义输入与已选列表一起保存草稿；直接保存时纳入尚未点击添加的输入，超限则提示并保留草稿。
- 卡片显示前 3 个标签，多出的显示“＋N”；详情在药名区域之后直接展示全部标签，无标签时不占位。组卡片显示标明“组内标签”的去重摘要，组内每条库存显示自己的标签，不将组标签写回记录。首页的按需筛选面板只显示库存实际使用的标签；一次按一个标签精确筛选，与搜索、有效期筛选取交集。搜索匹配名称、功效、备注及标签文本。
- 筛选标签即使已无记录仍保留可见，方便清除；无匹配时“查看全部药品”清除全部条件。保存或撤销移除后也清除全部条件并定位记录。
- 标签随库存记录存储，不增加独立分类管理、自动分类、标签重命名或批量编辑功能。

## 品牌资料与说明书

- 原药品名称继续作为库存标题，通用名、品牌 / 商品名另行选填；不依据品牌推断成分或剂量。
- 基本资料还包括规格 / 包装、生产厂家、批准文号、生产批号、存放位置。规格不等于一次服用量，存放位置不等于说明书要求的贮藏条件。
- 说明书记录成分、用法用量、禁忌、不良反应、注意事项、药物相互作用、贮藏条件和来源 / 修订日期。适应症 / 功能主治沿用原 `efficacy` 字段，不新增重复字段、不自动拆分旧备注。录入时可放大说明书照片核对，保存后默认仅保留选中的一张药品图；完整说明书请另行妥善保管。
- 所有新字段可留空，按“药品资料”“说明书记录”“备注”分组展开。基本资料各项最多 200 字符，不能包含换行或控制字符；说明书各项最多 5000 字符（来源最多 500），允许内部换行。保存去首尾空白，超长保留草稿并提示，不静默截断。
- 说明书仅为用户从当前同厂家、同规格包装/说明书手工记录的原文；可从明确的 OCR 章节标题生成候选，但不是药品库查询、在线抓取、临床决策或个体服药指导；识别原文必须逐项核对。空白不代表没有禁忌、副作用或相互作用，详情始终提示查阅实际说明书及咨询专业人员。
- 首页搜索纳入全部基本资料，与标签/有效期筛选保持交集；说明书安全条目不纳入首页搜索，避免禁忌中出现的疾病被误认为适应症。仍保留原功效文字的搜索。
- 新字段进入 SavedStateHandle 草稿与 baseline，对未保存返回、编辑、更新余量、删除与撤销保持同一数据生命周期；不引入新的账号、联网依赖或权限。

## 拍照与核对

1. 拍药盒正面，可继续补拍盒底、侧面有效期。
2. 将照片复制到应用私有持久目录，不依赖相册临时授权或缓存寿命。
3. ML Kit 本地识别，显示原文和明确标签匹配到的候选字段。
4. 药名匹配名称标签；未带标签的独立剂型名称行只作为手动选择候选，不取第一行猜名。有效期只匹配“有效期至”等明确到期标签，不使用生产日期或“24 个月”；用户框选并指定有效期时允许明确的孤立日期。
5. 候选通过“采用”显式写入空字段；已有填写时禁用采用，不覆盖人工内容。
6. 用户对照照片核对名称和有效期后勾选确认。字段仍可手动填写或留空。
7. 选择一张药品图（默认第一张）。保存过程中禁用重复提交与离开；数据库完成写入后才返回药箱并清理其余本次识别图。失败保留草稿，确认放弃编辑只清理本次新增图。
8. 旧多图记录不自动清理；在编辑页明确确认仅保留选中图片后，成功保存才清理其他旧图。其他记录或可撤销记录引用的文件保留。

没有候选不代表没有识别到文字；可以查看原文后手动录入。识别失败、取消拍照或拒绝权限不会阻断手动录入。首次授予相机权限后直接继续拍摄。

## 数据规则

- 名称必填。
- 到期日可用日期选择器填写，或手动输入严格的 `YYYY-MM-DD`、`YYYY-MM` 月份精度（以该月末计算）。不支持将期限与生产日期自动换算为到期日。
- 余量是非负整数，有数量必须选单位。空值表示未知，0 表示已用完。不跨单位合计，也不把所有单位统一定义为 `≤3` 低余量。
- 药品资料、说明书（含原包装功效）、备注渐进展开，原文记录不作为用药建议。
- 一次录入最多使用 12 张识别照片，支持放大和双指缩放；新录入只长期保留选中的一张药品图。旧多图记录和备份保持兼容，普通编辑保留全部旧图；明确确认后才可缩减为单图。
- 草稿、页面、筛选等经 SavedStateHandle 保存，支持旋转和 Android 保存状态后的进程重建；不承诺强制停止或清除任务后的草稿恢复。
- 返回未保存的编辑页需确认放弃。添加或更新成功返回全部库存并定位记录。
- 单条移出入口直接放在详情上方药名下方，无需滚动到底或寻找隐藏菜单；首页列表旁直接提供「批量管理」。
- 批量管理按独立库存展开药品组，显示品牌/规格、批号、有效期、余量与位置；勾选单条或「全选当前结果」只作用于当前搜索/筛选结果，不隐式选中隐藏记录或同组其他记录。改变搜索/筛选会清空勾选，「完成」或系统返回退出管理，未确认不删除。批量移出按钮放在 Scaffold 固定底栏，撤销提示显示在它上方，不遮挡连续操作。
- 移出需确认，预览条数及前 6 条记录（更多记录可取消返回列表核对）；数据库事务重新读取全部确认 ID，缺失任何一条则整批失败，大批量分段执行但在同一事务中提交。无需数据库升级。
- 通过随后提示条可以撤销整批移出，恢复完整资料、照片、时间、标签和分组；恢复与删除都在事务内完成，已存在相同 ID 时拒绝覆盖且不部分恢复。仅保留最近一批的内存快照，提示条结束后不可撤销，进程终止也不提供恢复，不是长期回收站。每个提示条绑定本批标识，旧提示不会恢复或清除新批次。新批提示在旧批照片清理前发布，立即替换旧提示，不排队展示已失效的撤销入口；若替换前尚未请求撤销，旧批提示窗口结束。同批清理失败只更新提示文字、保留撤销窗口；清理期间的撤销点击等待 busy 结束后按本批标识恢复，无需再次点击。
- 可撤销期间保护整批照片；提示条消失或新批次取代旧批次时，只清理这些记录曾引用且当前数据库、草稿、baseline 或新可撤销批次不再引用的应用私有照片。到期清理等待当前写操作结束、重新核对本批标识后占用 busy；删除事务发布撤销快照前也保护在途照片，避免共享照片竞态。清理失败提示但不回滚删除；不扫描未知文件、不删除相册原文件，异常退出可能遗留照片。

## 旧版本兼容

Room 版本 2 → 3 仅增加数量单位、多图及更新时间字段；3 → 4 仅增加 `tags_json TEXT NOT NULL DEFAULT '[]'`，旧记录默认为无标签。4 → 5 增加 15 个 `info_* TEXT NOT NULL DEFAULT ''` 显式字段，使用 `@Embedded` 资料对象组织；历史迁移中的字段列表固定，不依赖后续版本可扩展的枚举。6 → 7 增加 `info_production_date TEXT NOT NULL DEFAULT ''`，独立于有效期，旧记录留空不自动推断。迁移链保留旧字段和创建时间。移除 destructive fallback，缺少迁移时显式失败而不是清空记录。

- 原数字余量保留，单位为空时显示“单位待补充”。
- 无法解析的旧有效期保留原文并提示核对，不参与有效/过期判断。
- 旧缓存照片还存在且可读取时转存私有目录；已经丢失的照片无法恢复。
- 更新余量或编辑资料不改创建时间，不自动合并同名药品。

## 必要 UT 与按需检查

保留 9 个药箱纯规则 UT，集中在日期精度与无效值、临期边界、表单/余量校验、明确标签候选、生产日期排除、标签规范化与边界限制、标签和文字组合匹配、资料字段独立性与多行原文保留、资料边界与搜索范围。不引入额外测试框架，不保留新增的 UI／仪器测试套件。

构建和 Lint 用于发现编译及静态问题。页面、旧数据迁移、权限与 OCR 实际照片效果在专用设备上按需检查，不以规则 UT 代替实际功能验证。

## GitHub 应用更新

- 首页右上角“更多 → 关于”展示当前安装版本、项目介绍、非商业许可说明及项目主页入口。项目许可、第三方通知、隐私说明通过独立可滚动阅读器读取随包文本，不主动发起网络请求；SDK 指标通信边界见[隐私说明](privacy.md)，不承诺启动时所有 SDK 均离线。
- 「关于」内点击“检查更新”直接读取 `releases/latest/download/update.json`，不调用 REST API；将元数据版本/编码/哈希/大小与本仓库版本化跳转绑定，APK 固定到检查出的版本。404 提示可能尚未发布或附件缺失，不把缺文件说成已最新。
- 有新版时展示版本、大小，说明通过“浏览器下载 / 发布说明”查看；该入口始终可用，已有结果时打开固定版本页面。浏览器下载不经过应用内校验，明确提醒仅选官方附件、不卸载或清空药箱。超时、DNS、TLS、HTTP、校验失败安全分类，不显示原始异常/签名跳转 URL。
- 用户点击后才下载；下载进度跨旋转保留，关闭对话框不取消下载，进程终止后需重新检查/下载。
- 下载到专用缓存目录，开始新下载前清理旧 APK/临时文件，最多保留一个完成的更新包；仅通过 HTTPS 获取本仓库资源，校验 SHA-256、大小、包名、版本和当前签名，不触碰 Room 或照片目录。
- 校验通过后用户点“安装更新”，必要时打开 Android 未知来源授权页；返回后请求系统安装，最终仍由用户确认。拒绝授权、取消安装或失败不清除药箱。
- 历史调试 APK 可能使用不同签名；不一致时明确阻止覆盖并提醒先保留/备份数据，绝不自动卸载。备份导出与安全合并恢复见 [backup-restore.md](backup-restore.md)；签名迁移仍需先确认备份可用。
- main CI 使用固定私有调试签名，发布带校验元信息的公开 Release；PR 不访问该签名、不发布。保留 3 个纯更新规则 UT 并补充发布跳转/元数据绑定覆盖，增加 1 个安全错误分类 UT，不引入测试框架。
