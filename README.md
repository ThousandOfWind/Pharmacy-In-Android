一个药箱数据主要保存在本地、日常管理可离线使用的安卓小程序。应用主动检查/下载 GitHub 更新及使用 Azure AI 时联网；ML Kit OCR 在设备上处理图片与结果，但 SDK 可能联网并向 Google 发送性能/使用指标。系统备份及用户选择的云端文件提供方也可能处理数据，详见[隐私说明](docs/privacy.md)。交互围绕「看药箱 → 拍照核对 → 入库 → 更新余量」组织：

- **手绘药箱首页**：手绘字标、药品清单、搜索和必要的过期/临期提醒；有效期与标签筛选按需展开（可叠加），不堆积在首屏。
- **多标签整理**：常用标签快捷多选、自定义标签和已有标签复用；首页卡片显示前 3 个标签及剩余数量，详情直接展示全部标签，首页按需筛选，搜索包含标签。
- **独立添加页**：拍照、相册或手动录入；保存按钮固定在底部，未保存返回时确认放弃。
- **再次编辑**：默认基本资料页直接修改名称、日期、余量、位置、品牌、规格、厂家、批号和标签；说明书、照片/原文独立分页。不因历史OCR显示空候选或要求重复核对，补拍/重识别才展示本次候选。
- **本地中文 OCR 与归类**：识别建议直接附在对应名称、日期、厂家、规格等输入栏，不另设大候选卡；采用后在同一栏修改。照片中的明确说明书章节需逐项核对，不覆盖已有填写。
- **顶部固定添加入口**：拍照/相册按钮不随长表单或候选滚出；添加与编辑使用基本资料、说明书、照片/识别分页。底部核对框可反复勾选/取消。
- **框选重识别与照片管理**：照片下直接旋转90°，生成像素方向已校正的PNG副本（大图缩小至长边不超过2400像素），旧记录原文件在成功保存前保留，本次导入的临时原图被旋转副本替换后可能立即清理；整图/框选重识别及确认后删除。取消编辑保留旧记录。
- **可复制的识别原文**：长按选择/复制原文，可粘贴并指定填入空白资料栏；字段旁的识别文本与采用按钮区分，保存前固定核对整行可点击、勾选或取消。
- **常用标签识别建议**：从明确的适应症、用法用量、贮藏章节提取标签并展示依据，逐项点击采用，不根据药名、禁忌或注意事项推断。
- **药品详情**：先看有效期、余量与位置；包装资料、照片和说明书按组展开，支持放大照片、底部面板更新余量、编辑资料；药名下方直接显示「移出药箱」，无需滚动到底或寻找隐藏菜单。
- **批量移出**：首页「批量管理」勾选独立库存或全选当前搜索/筛选结果；分组展开，不误选隐藏记录。确认后原子移出，提示条可撤销整批，不是长期回收站。
- **药品资料与说明书**：通用名、品牌、厂家、批号及位置等均可选；说明书可由 OCR 标题归类后逐项核对，或手工记录，不自动生成剂量或用药建议。
- **余量＋单位**：区分未知与 0，不跨单位相加，不使用统一低余量阈值。
- **本地持久保存**：Room 数据库、应用私有目录照片、屏幕旋转和系统重建时恢复填写草稿。
- **可选 Azure AI 助手**：自有资源/API Key/deployment、流式对话、本地会话；用户明确允许后才用只读工具查询库存基本资料，不上传照片、备注或说明书，不修改药箱。
- **药品组与独立库存**：同药不同品牌、规格、批次可由用户明确关联；首页收纳，组内查看各条有效期、余量与位置，不合并资料或跨单位求和。
- **备份与换机**：更多菜单导出完整药箱与照片，回读核对保存文件；自行传到新手机后校验、预览并合并导入，不覆盖现有药箱。空药箱提供旧手机导入入口，完成后引导核对。无需自建服务器，系统备份保持现状；ZIP 未加密，请妥善保管。
- **关于与更新**：首页“更多 → 关于”查看当前版本、项目介绍和项目主页；点击“检查更新”直接读取公开 Release 的 `update.json`（不调用 GitHub API），手动下载并校验后交给 Android 确认安装，不上传药箱数据或保存 GitHub 凭据。

## 数据字段

- 药品名称（必填）
- 有效期至（可选，`YYYY-MM` 或 `YYYY-MM-DD`；月份精度按月末计算）
- 生产日期（可选，`YYYY-MM` 或 `YYYY-MM-DD`，独立于到期日期，不推算有效期）
- 适应症 / 功能主治（可选，沿用原主要功效字段）
- 药品资料（可选）：通用名、品牌 / 商品名、规格 / 包装、生产厂家、批准文号、生产批号、存放位置
- 说明书（可选）：成分、用法用量、禁忌、不良反应 / 副作用、注意事项、药物相互作用、贮藏条件、说明书来源 / 修订日期
- 余量及单位（可选，非负整数；有数量时必须选择单位）
- 标签（可选，每条最多 8 个，每个最多 12 个字符，去除首尾空白并忽略大小写去重）
- 备注（可选）
- 药品图（可选，新录入默认只长期保留一张；录入时可使用最多 12 张正面、有效期、说明书等照片用于识别与核对）

添加/编辑按基本资料、说明书、照片/原文分页，输入栏直接展示，不要求一次填完整；详情仍按组展开。原药品名称保留为库存列表标题，通用名与品牌可单独记录；不同厂家、规格、批号或有效期的库存建议分开添加。基本资料每项最多 200 个字符；说明书各项最多 5000 个字符，来源 / 修订日期最多 500 个字符。保存仅去首尾空白，保留说明书内部换行；超长提示而不静默截断，请精简填写并另行妥善保管完整说明书。

**说明书是包装原文记录，不是在线查询或用药建议。OCR 可按明确标题归类候选，但错字、漏字不能保证自动修正，必须核对当前同厂家同规格的原图。** 内容应来自当前药品同厂家、同规格的包装或说明书；不会根据药名、品牌、标签生成剂量，也不将留空解释为“无禁忌 / 无副作用”。有疑问应咨询医生或药师。旧备注与功效不自动拆分，原文保留；新资料全部默认为空。

搜索匹配库存名称、标签、功效、备注及全部基本资料（含品牌、通用名、规格、厂家、批准文号、批号和存放位置）。说明书安全条目不参与首页搜索，避免把禁忌中提到的疾病误认为适应症。

## 常用标签

常用标签只是可选的整理词，不会自动分配，也不代表适应症或用药建议：

| 分组 | 标签 |
| --- | --- |
| 用途整理 | 感冒相关、退热、止痛、过敏相关、肠胃相关、咽喉相关、眼部、皮肤相关 |
| 使用方式 | 口服、外用 |
| 备用场景 | 家庭常备、出行备用 |
| 保存提示 | 需冷藏、避光保存 |

用途、使用方式和保存条件应自行核对包装。OCR 可从明确章节生成常用标签建议：用途仅来自适应症/功能主治，口服/外用来自用法用量，冷藏/避光来自贮藏条件；包含否定或禁止字样的句子不生成建议。建议展示原文依据，用户点击后才添加；不自动分配家庭常备/出行备用，不覆盖或删除已有标签。可以新增如“床头抽屉”“急救包”的自定义标签，后续记录可复用。点击已选标签可移除；直接保存也会加入自定义输入框里尚未点击添加的标签。标签筛选使用精确匹配，搜索使用文字包含匹配；无匹配时“查看全部药品”会同时清除搜索、有效期和标签筛选。

## 本地开发与构建（Windows）

环境要求：

- JDK 17，配置 `JAVA_HOME`，将 `%JAVA_HOME%\bin` 加入 `PATH`。
- Android SDK，安装 `platform-tools`、`platforms;android-34` 和 `build-tools;34.0.0`，并接受对应 SDK 许可。
- 配置 `ANDROID_HOME` 指向 SDK，将 `%ANDROID_HOME%\platform-tools` 加入 `PATH`。
- 在项目根目录创建 `local.properties`（已被 Git 忽略），填写本机 SDK 路径，例如：

```properties
sdk.dir=C:/Users/zhiruizhu/AppData/Local/Android/Sdk
```

本仓库自带 Gradle Wrapper，无需额外安装 Gradle。在项目根目录运行：

```powershell
.\gradlew.bat --no-daemon assembleDebug
.\gradlew.bat --no-daemon testDebugUnitTest lintDebug
```

APK 输出：`app/build/outputs/apk/debug/app-debug.apk`。
Lint 报告：`app/build/reports/lint-results-debug.html`。

## APK Pipeline（GitHub Actions）

仓库已配置自动构建 APK 的流水线：

- Workflow 文件：`.github/workflows/build-apk.yml`
- 触发方式：
  - 手动触发（`workflow_dispatch`）
  - 推送到 `main/master`
  - Pull Request
- PR / 非 main 构建：仅验证和上传 `pharmacy-debug-apk` artifact，不发布更新、不使用固定签名私钥。
- main 构建：UT、Lint、APK 构建通过后，上传 artifact 并自动发布公开 Release（APK + `update.json`）。
- 自动版本：`versionName = 1.0.<workflow run_number>`，`versionCode = run_number + 1`。版本可有间隔，重跑同一版本不替换已发布文件。只将比已有版本更新的发布标记为 latest。
- 固定调试签名保存在仓库 Actions secret `PHARMACY_DEBUG_KEYSTORE` 中，私钥不进入 Git/日志/artifact；只在 main 构建临时恢复并清理。缺少 secret 时拒绝用临时签名发布。
- 不要删除或轮换该 secret，否则后续 APK 无法覆盖现有安装。本地/PR APK 的签名不能作为 main 更新通道使用。

## 下载及应用内更新

1. 打开仓库的 [最新 Release](https://github.com/ThousandOfWind/Pharmacy-In-Android/releases/latest)。
2. 下载附件 `app-debug.apk`，传到手机安装。公开 Release 下载不需要 GitHub 登录。
3. 后续在药箱首页点击 **更多 → 关于 → 检查更新** → **下载更新** → **安装更新**。首次可能需在系统设置中允许本应用安装未知应用，返回后仍由系统确认安装。

检查更新直接读取 `https://github.com/ThousandOfWind/Pharmacy-In-Android/releases/latest/download/update.json`，不调用 REST API、不要求登录或 Token，避免 VPN 共享出口的匿名 API 限流。校验元数据版本与本仓库版本化跳转一致后，下载地址固定到该版本，避免 latest 在检查后变化；不读取元数据中的任意下载 URL。发布说明通过浏览器查看。

检查/下载失败会区分超时、DNS、安全连接、HTTP 和校验问题；“浏览器下载 / 发布说明”始终提供官方发布页入口（已有检查结果时固定到该版本）。浏览器下载不经过应用内 SHA-256/包名/版本/签名校验，不保证与当前版本兼容；只选择官方 `app-debug.apk`，安装由 Android 确认。不要卸载或清除数据。首次取得这个修复版时，旧应用仍使用旧 API，需要先从发布页手动下载覆盖安装。

此方案仍依赖 GitHub Release/CDN 的可达性；浏览器和药箱可能走不同 VPN 分应用代理，不能保证国内网络均可用。没有加入第三方镜像、凭据或降低 TLS 校验要求。

下载只允许本仓库 Release 和受信任的 GitHub HTTPS 下载跳转；校验 SHA-256、大小（最大 150 MiB）、包名、版本及与已安装应用一致的签名。不支持静默安装或自动卸载。网络失败、缺少发布或拒绝授权不会影响本地药箱。

**旧 APK 迁移注意：** 历史 Actions/本地 APK 的签名可能不同；新固定签名不保证能覆盖旧安装。签名不一致时应用内更新会阻止安装。请保留旧应用及药箱数据，不要直接卸载或清除数据；请先在“更多 → 备份与换机”导出完整备份并确认可恢复，再规划迁移；旧版本不一定具备该入口，不能因此直接卸载。首次使用固定签名 APK 后，后续同签名新版才能正常覆盖并保留数据。

Actions 的 `pharmacy-debug-apk` artifact 仍保留，内含 APK 与 `update.json`；下载 artifact 通常需要 GitHub 登录。应用更新使用公开 Release，不使用该下载入口。

## 说明

当前为本地药箱管理第一版，不提供用药建议或自动服药计划。OCR 只提取明确标注的候选字段；生产日期和有效期时长不会被当作到期日期。保存前应以实际包装为准。

数据库版本 7 使用显式的版本 2 → 3 → 4 → 5 → 6 → 7 迁移，不再静默清空旧记录。版本 3 → 4 只新增默认为空数组的标签字段；4 → 5 只新增默认为空文本的 15 个药品资料/说明书字段，旧药品、照片、标签、功效、备注、余量和时间信息保留，不自动推断或拆分内容。6 → 7 只新增默认为空的生产日期，旧数据保留；备份v3保存生产日期，v1/v2恢复时生产日期留空，旧版应用不能读取v3备份。5 → 6 增加空的分组UUID和名称；旧记录保持未分组，不按药名自动合并。旧记录缺失单位或有效期格式不明确时，显示待补充/待核对，不自动推断。旧缓存照片若仍可读取，会转存到应用私有目录；已丢失的缓存照片无法恢复。

录入时默认以第一张为药品图，也可点击「设为药品图」更换。核对并成功保存后，仅长期保留选中的药品图，其余本次识别照片清理；保存失败保留草稿，确认放弃编辑只清理本次新增照片。旧记录和旧备份恢复的多张照片不自动删除，普通编辑保存也保留；在编辑页明确确认「仅保留这张」后，成功保存才清理其他照片。清理不删除相册原文件，也不删除其他记录、当前草稿或可撤销记录引用的文件；清理失败会提示，不回滚已保存资料。不提供全目录孤立文件扫描；异常退出可能遗留未清理文件。

药品图保存在应用私有目录，清缓存不会删除；卸载应用或清除应用数据仍会删除药箱。可以导出完整备份及合并恢复；备份只含仍保留的照片，不含已清理的识别临时图。资料和 OCR 原文仍保留，但删除的原图无法再查看或框选重识别，需要重新拍摄。可单独删除照片：草稿中移除，保存后清理不再引用的文件；删除清空待采用候选，历史原文和已填写资料保留。暂不提供覆盖式回滚或长期撤销历史。AI 会话单独本地保存，可删除；Key 与会话不进入系统或药箱备份，删除对话不撤销 Azure 已收到的数据。
